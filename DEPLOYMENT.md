# Dane County War Room - GitHub Pages Deployment

## 🚀 Quick Deploy Instructions

### Step 1: Create GitHub Repository
1. Go to [github.com/new](https://github.com/new)
2. Name it: `dane-county-war-room`
3. Keep it **Public** (required for GitHub Pages on free plan)
4. Don't initialize with README (we already have code)
5. Click "Create repository"

### Step 2: Push Code to GitHub
```bash
cd /Users/tylerherman/Desktop/AntiGravity/dane-county-war-room

# Add your GitHub repo as remote (replace YOUR_USERNAME)
git remote add origin https://github.com/YOUR_USERNAME/dane-county-war-room.git

# Push to GitHub
git branch -M main
git push -u origin main
```

### Step 3: Enable GitHub Pages
1. Go to your repository on GitHub
2. Click **Settings** → **Pages** (in left sidebar)
3. Under "Build and deployment":
   - Source: **GitHub Actions**
4. The deployment will start automatically!

### Step 4: Get Your Live URL
After ~2-3 minutes, your dashboard will be live at:
```
https://YOUR_USERNAME.github.io/dane-county-war-room/
```

## ⚠️ Single Points of Failure to Know About

- **Hosting**: GitHub Pages is the only deploy target — there is no mirror
  or fallback host. A GitHub-wide outage (rare, but it happens) would take
  the whole dashboard down with no backup. If uptime on election night is
  critical, consider a secondary deploy target (e.g. Netlify or Vercel from
  the same repo) that the team can switch to via DNS/link if GitHub Pages
  is ever down.
- **Live data**: the app calls `api.danecounty.gov` directly from each
  visitor's browser. If the county's API is slow or down, the dashboard
  keeps showing the last successfully-fetched results (it does not go
  blank) and retries automatically — but nobody sees newer numbers until
  the county's API recovers. This is the county's infrastructure, not
  something this app can route around.
- **Build-time data** (`public/historical-ward-data.json`,
  `public/ad76-planning.json`): generated by the `prebuild` scripts, which
  now preserve the last successful run's data if a build-time fetch fails,
  rather than overwriting it with an empty file. A failed prebuild fetch no
  longer risks deploying a blank Planning tab or historical baseline.
